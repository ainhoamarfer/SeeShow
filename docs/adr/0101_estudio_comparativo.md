He elegido Android nativo, Flutter y PWA

1. Android nativo

Lenguaje y herramientas: 
principalmente Kotlin. Se utiliza Android Studio junto con el SDK de Android.

Plataformas: 
está orientado principalmente a dispositivos Android.

Rendimiento y hardware: 
tiene un rendimiento muy bueno y permite acceder directamente a funciones del dispositivo como la cámara, GPS, Bluetooth o sensores.

Coste de desarrollo y mantenimiento: 
si solo se desarrolla para Android, el coste es relativamente bajo. Sin embargo, si también se quiere una aplicación para iOS, 
habría que desarrollarla por separado.

Caso de uso: 
sería una buena opción para una aplicación que necesite utilizar mucho el hardware del móvil, por ejemplo, 
una aplicación para un dispositivo industrial que utilice sensores, GPS y Bluetooth.

2. Flutter

Lenguaje y herramientas: 
utiliza Dart y el framework Flutter. Se puede trabajar con Android Studio o Visual Studio Code.

Plataformas: 
permite desarrollar aplicaciones para Android, iOS, web y escritorio.

Rendimiento y hardware: 
ofrece un buen rendimiento y permite acceder a muchas funciones del dispositivo mediante plugins.

Coste de desarrollo y mantenimiento: 
permite reutilizar gran parte del código entre Android e iOS, por lo que se reduce el tiempo de desarrollo y mantenimiento.

Caso de uso: 
sería una buena opción para una aplicación de reservas de un restaurante que necesite funcionar tanto en Android como en iOS, ya que se puede desarrollar gran parte de la aplicación una sola vez.

3. PWA

Lenguaje y herramientas: 
utiliza tecnologías web como HTML, CSS y JavaScript. Se puede desarrollar con herramientas como Visual Studio Code.

Plataformas: 
funciona mediante navegadores y puede utilizarse en Android, iOS, Windows y otros sistemas.

Rendimiento y hardware: 
tiene un rendimiento menor que una aplicación nativa y el acceso al hardware depende de las funciones que permita el navegador.

Coste de desarrollo y mantenimiento: 
tiene un coste bastante bajo porque se puede utilizar el mismo código para diferentes dispositivos y no es necesario crear una aplicación independiente para cada plataforma.

Caso de uso: 
sería una buena opción para una aplicación de gestión de pedidos de una pequeña empresa, ya que los usuarios podrían acceder desde el navegador sin necesidad de instalar una aplicación desde una tienda.
